# Test cases from the assignment branch

> [!NOTE] Review note (2026-11-21)
> Reference inventory (2026-11-19) of 136 test cases from retired tag `archive/v1-assignment-integration`. Candidate cases remain relevant for `TASK-49` (B4/B5); apply `ADR-0031` (no task-capability grant) and `ADR-0010` (legacy adoption withdrawn) when porting.

Written 2026-11-19 against v1 at `d0945749`. **Status:** reference material, not
requirements.

The branch `codex/v1-assignment-integration` built a task assignment and task
adoption model (the "selected" task model) on the office and host code of
2026-11-15. v1 has since replaced most of that code, so the branch is retired. It is
kept as the tag `archive/v1-assignment-integration` (`4e395c12`: the branch head
`59f5e143` plus its uncommitted documentation).

This page lists the 136 tests that branch wrote whose names appear nowhere on v1,
plus the 12 steps of its one browser journey test. The code does not compile on v1,
so only the cases are carried over. The requirement documents, the data
contract and the ADRs decide what applies. Check each case against them first, in
particular [ADR-0031](../adr/0031-any-employee-changes-tasks.md) (any employee changes
tasks, so there is no task capability to grant),
[ADR-0019](../adr/0019-office-coded-task-numbers.md) (office-coded task numbers) and
[assignment and history](../design/organization-data/12-task-assignment-and-history.md).

The wire vectors that the `org-proto` tests read are in
`crates/org-proto/test-vectors/v2/selected-tasks-v1.json` on the tag; v1 has no copy.

To read a test's code:

```sh
git show archive/v1-assignment-integration:<file on the branch>
```

How the list was made: every `#[test]` function (including ones generated by a test
macro), every `it` or `test` title and every Playwright `test.step` title in a file
the branch added or changed after `73a39c58`, kept when its name appears nowhere in
`crates/` or `apps/` on v1 and did not already exist at `73a39c58`. 143 older tests
that v1 deleted itself are left out, and so is one helper (`acceptance_crash_child`,
the child process of the SIGKILL reopen test). One listed entry,
`selected_browser_fixture_uses_actual_protected_setup_and_adoption_until_explicit_stop`,
is an ignored fixture that served the browser journey rather than a case of its own.
Names were compared, not behaviour, so a case listed here may already be covered on v1
by a test with another name.
