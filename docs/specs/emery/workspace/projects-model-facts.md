# Projects model facts (Explore, 2026-11-12, origin/v1 of /Users/vgmello/projects/agentic-consulting/app)

"design" = docs/design/tasks-projects-docs.md.

1. **Project identity.** A project has a human `key` and no number. The key is 2-10 lowercase ASCII letters or digits, starts with a letter, is unique in the org and immutable. Reserved: req, feat, adr, eval, debt, lim, exc (crates/org-proto/src/org.rs:527-532, 582-589; design:143). The name is unique, ignoring case (org.rs:590). Storage: org.db `projects (id TEXT PRIMARY KEY, body TEXT)`, ULID id + JSON body (crates/org-office/src/store/org.rs:107). Lookup by key is a json_extract scan with no index or unique constraint (store/org/work_view.rs:97-104).
2. **Work numbering.** Scopes: tasks per project, bugs per project, requests per org (crates/org-work/src/ports.rs:73-77; design:298). Counter table `work_number_counters(scope PK, last)` with an atomic upsert RETURNING (crates/org-office/src/store/work/metadata.rs:31-32, 106-122), inside the single office writer transaction (store/work.rs:2-3); tests crates/org-work/src/tests/numbering.rs:9,37. Format "T-12"; outside the project `chk-T-12`; requests `REQ-14` (design:47-55; crates/org-work/src/refs.rs:15-21). The CLI `<ref>` takes a qualified number, an unqualified T-12 (resolved in --project or the current task's project) or a 6-char short id (design:814). The app writes with the ULID (crates/org-proto/src/work.rs:46-48, 360).
3. **Releases, milestones.** None. "Version" is optimistic concurrency only (work.rs:428-429). Features: designed for phase 3, proto type exists (work.rs:681-702): Markdown doc in the project repo + HQ record {id, project_id, number FEAT-n, path, title, status proposed|planned|in_progress|delivered|retired, delivered_at?}; tasks link via feature_id (design:138-139; work.rs:389-391); designed `doc_numbers` table (design:301, 449). No due/target date on a project (design:142).
4. **Backlog / unplanned.** Not found anywhere.
5. **Storage keys.** `work_items (id TEXT PRIMARY KEY, generation, version, data TEXT)` JSON keyed by ULID; `work_ids` claims permanent ULIDs; `work_events` keyed by (target_id, version) (store/work.rs:20-39). No index on project or number; metadata.rs:13 probes json_extract(data,'$.number'). The designed unique index (kind, number_scope, number) (design:430) isn't built. `WorkReads::by_number` is a trait method (ports.rs:183) and in the testkit (testkit.rs:346); no office-store implementation.
6. **Cross-office.** Phase 2 design: offices create items under client-made ULIDs; only HQ assigns numbers. A satellite item shows "Pending · short id" until HQ numbers it and streams `ItemNumbered { item_id, number }`, an HQ record, not an item version (design:299-300; work.rs:982-984). Phase 1 is HQ only (design:299).
