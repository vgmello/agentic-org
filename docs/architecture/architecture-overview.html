Agentic Org · Architecture

Architecture overview

Agentic Org is a self-hosted server that runs an organization of AI agents and people: teams, projects, tasks, chat, Git worktrees, multi-office federation, and spend, with agents launched and supervised on macOS and Linux machines you control. This page is the map: what each part owns, where truth lives, what runs live on v1 today, and what remains across m-0 (v1) and m-1 (v2).

01The product in one minute

An owner installs one server on macOS, Linux, or inside a container, opens the browser directly into onboarding (HTTP and authless by default on local HQ, with opt-in accounts and HTTPS), creates an organization, and staffs it with people and AI agents. The server keeps organization structure and work as canonical files with rebuildable SQLite projections, runs each agent as a supervised headless child process (claude, codex, or agy), routes messages across offices over Org-CA mTLS, manages isolated task Git worktrees, and tracks usage and budgets.

  • Organization. A recursive tree of teams. Every employee, agent or person, has exactly one home team.
  • Offices. The machines where agents run. One office is HQ and holds organization authority. Satellites run the same worker binary on remote macOS/Linux hosts and connect out to HQ over Org-CA mTLS.
  • Work. Projects contain typed tasks (task, bug, request) with office-minted references (T-A1, T-B37), checklists, dependencies, and immutable history; features, releases, deployments, and versioned project docs complete the model.
  • Two separate guidance primitives. Organization processes and standards auto-inject along a single inheritance chain (org → team → project). Development processes (composable bundles such as DSS, Kanban Flow, and Feature Delivery) are content, never an execution engine (ADR-0026).
  • Two front doors. People use a static SvelteKit browser app served by agentic-org-web. Agents use the agent-os command-line tool (92 commands + session attach, zero MCP wrappers).
  • Files first. Canonical records live under durable/; runtime/<office-id>/ SQLite projections and worktrees are rebuildable caches.

The desktop shell was removed in ADR-0005, and the repository is unified under FSL-1.1-ALv2 (Tailwind Plus removed in TASK-122/123). All v1 integration lands directly on v1.

02System at a glance

Four thin Rust executables (composed from 29 library crates), one static SvelteKit SPA, and three native headless agent runtimes supervised by the office worker.

Live dogfooding on v1 (2026-11-26). All three core milestones run in production paths today: local macOS HQ and remote Linux satellites over private mTLS/VPN networks exchange Org-CA mTLS sync and cross-office agent wakes, launch sandboxed Claude/Codex/Agy agents in isolated homes and task worktrees, and serve the live SvelteKit UI. Remaining m-0 work focuses on AX skills/onboarding, task-engine and query-hygiene upgrades, persistent bidirectional mTLS & push SSE, HQ→satellite session proxying, composable docs/processes/search/reviews/attachments, and Embedded Tess v1.

Install, onboarding, auth, and HTTP/HTTPS (ADR-0032, ADR-0033, ADR-0034)

  • Prebuilt binaries and one-command install. Prebuilt macOS and Linux release packages and a fail-closed install.sh (no remote Rust compilation, no python3 prerequisite) shipped in TASK-121/125. Automatic pull-verified background updates and service unit refresh remain in TASK-60, TASK-134, and TASK-155.
  • Local HQ starts HTTP-only and authless directly into the onboarding wizard (ADR-0033, ADR-0034). Installing and running a local HQ server requires zero up-front TLS certificates or password ceremony: the browser opens straight into onboarding over HTTP (TASK-62, TASK-76). Both account authentication (multi-person invites, password sign-in, stored sessions) and HTTPS (self-signed or operator-supplied PEM with live rotation and HSTS via POST /api/v1/instance/tls or agentic-org admin tls set) are opt-in inside Settings → Security & Access.
  • Browser-driven CLI sign-in enrollment & permission presets (ADR-0032). Operators connect Claude (paste_code via claude setup-token / auth login --claudeai) and Codex (device_code via codex login --device-auth) subscriptions from the browser through a narrow, bounded, ephemeral enrollment PTY (never an agent terminal). Extracted tokens are wiped from the temp dir and wrapped by the office worker under an HKDF-separated wrapping key (KeyClass::ProviderCredential, domain agentic-org/provider-credential/v1). Every agent's execution config selects one of four safe permission presets—safe_ask (default), read_only, workspace_edits, or autonomous_sandboxed—with workspace OS sandbox enabled and no unrestricted/bypass mode in product code.
  • Accounts, people, and agents. When auth is enabled, accounts and stored browser sessions belong strictly to org-host (host-registry.db); the office and web process never hold passwords. Sessions are stored as digests at the host and cached in memory by agentic-org-web so restarts of either process sign nobody out (ADR-0013). Every account maps to a person record; agents exist only as employees hired through built-in HR (no approval step; hiring requires may_hire or owner/admin authority, ADR-0029).

agent-os speed, session attach, and asking (ADR-0014, ADR-0020, ADR-0035)

  • Fast local path & session batching. agent-os talks directly to its local office Unix socket using org-command's single JSON envelope (ok, data, meta, error). agent-os session attach is built in crates/org-agent-cli/src/attach.rs, authenticating once and executing one JSON command per line with zero per-call process spawn overhead. Aligning hot task writes (CommentTask, ChecklistCheck, CreateTask with durable counter block reservation) to Ack::Committed and fixing tasks.list query pushdown are tracked in TASK-105 and TASK-87.
  • Bounded asks & non-destructive mid-turn delivery. Plain sends acknowledge office-locally in milliseconds and relay cross-office asynchronously. agent-os msg ask holds for at most one short hold (90 s default), returning waiting + ask ID for msg wait --ask; unanswered required asks suspend the agent cleanly and resume the same session on answer (ADR-0020). When an agent is mid-turn, urgent addressed messages (DMs, mentions, asks, handoffs, non-waiter-satisfied answers) are coalesced and delivered non-destructively at a step boundary via MidTurnDelivery (StepHook on Claude, NativeSteer on Codex and Agy ACP) without aborting running tools (ADR-0035).

How an agent gets its model Runs in v1

  1. An agent's execution config names its system prompt, one model profile, one model name, and one permission_preset. The system never picks an implicit default model.
  2. A model profile is an ordered pool of 1 to 64 provider connections. Each office holds its own local wrapped binding (durable/local/offices/<office-id>/auth/<connection-id>/) and discovered models (protected/providers.db).
  3. office_local vs hq_pool admission (TASK-2, TASK-54). Unshared per-office bindings admit and sustain turns locally even while disconnected from HQ ("Works alone"). Shared multi-office pools (hq_pool) request 60 s quota permits (renewed every 10 s) and shared rate-limit cooldowns from HQ, failing over safely across eligible pool connections for the same model.

04Domain model

The selected relationships from organization-data rev 2.24. Readable references such as T-B37 are labels; every record's identity is an immutable UUIDv7.

  • One home team, one lead per teamEvery employee belongs to exactly one team. The team lead is a direct member and manages the team's entire subtree. A separate optional reports_to line handles cross-team reporting.
  • Teams and projects live side by sideTeams exist at any depth before any project exists. Every project has one accountable owner team and optional contributing teams.
  • One typed task entitytask, bug, and request share one entity with office-minted references (T-A1, T-B37), independent assignment, first-class dependencies, searchable labels, modified files (TASK-77), and isolated per-author private notes (TASK-50, ADR-0031).
  • No hidden transition engineAny active employee changes task status (todo, in_progress, blocked, cancelled, done) with full history attribution (ADR-0031). Planned m-0 refinements add derived vs explicit blocking (TASK-84), DoD checklists with done_anyway gate (TASK-88), and first-class Universal Reviews RV-<OFFICE><N> (TASK-92).
  • Three clean knowledge/guidance primitives (doc-98, doc-99)(1) Organization processes & standards auto-inject along Org → Team chain → Project (TASK-44 backend done; UI wiring finishing); (2) Development processes ship as content packages—DSS, Kanban Flow, and Feature Delivery—with role skills and generic project tabs (TASK-56); (3) Dynamic project docs live in projects/<id>/docs/ with office-maintained index.yaml and immutable issued versions (TASK-55), searchable via unified 3-way isolated FTS5 (TASK-91).
  • Two-tier agent decision capture (doc-98, TASK-111/112)Planned in m-0: agents record private working decisions inside HQ's isolated private-notes DB (agent-os note --kind decision) with zero Git noise, and explicitly promote durable architectural choices to shared project ADRs (agent-os note promote) without leaking private provenance.

05Where truth lives

Files-first canonical storage is live on v1: durable/ holds every source of truth; runtime/<office-id>/ holds rebuildable projections and worktrees.

  • Office-local Git credentials (doc-35, TASK-161): Strict owner-only 0700 durable/local/offices/<office-id>/security/{git-https-helper,git-ssh-key,git-known-hosts} are resolved by org-office-server for office-mediated agent-os repo push, explicitly excluded from OfficeStore rebuild walks (while stray security/* files still fail closed), and denied to every agent sandbox.
  • No application-level DB encryption; private keys stay wrapped (ADR-0016). Plain SQLite (rusqlite bundled) is protected by disk encryption, 0700/0600 file permissions, and isolated companion DBs. Private keys (Org CA, office TLS) and provider credentials stay AEAD-wrapped using HKDF-separated keys derived from the host-held office secrets key (KeyClass::OfficePrivateKey vs KeyClass::ProviderCredential).
  • Agent isolation, private homes & Linux bwrap hardening (ADR-0015, TASK-126, TASK-144, TASK-159): Every agent runs in an isolated 0700 private home under durable/local/offices/<office-id>/agents/<employee-id>/home/. Read-only host Rust caches (.cargo/registry, .cargo/git, .rustup) are safely symlinked into the agent's isolated home (never symlinking host credentials* or config*) with writable CARGO_HOME=<agent_home>/.cargo and CARGO_NET_OFFLINE=true when sandboxed. On Linux Claude bwrap, non-existent permissions.deny path rules are pruned before launch (downgrading AcceptEdits → Ask when pruned) so bwrap never creates 0-byte 0444 host stub files, while keeping SessionManager's approval-bridge deny policy 100% intact. Stronger os-sandbox (TASK-57), dedicated OS user accounts (TASK-58), and Containers/Xcode extensions (TASK-59) are planned in m-0.
  • Storage scalability verdict (doc-100): Never split tasks.db out of office.db (0% write parallelism, breaks 9 FKs / 5 views / 15 triggers). Instead: v1 (m-0) ships SQL pushdown + batched hydration + open-by-default/7d cutoff + partial open indexes + Ack::Committed alignment (TASK-105, fixing the 9N tasks.list scan) and one-command local backup/verify/restore CLI (TASK-104); v2 (m-1) ships flusher decoupling + append-only messaging segments (TASK-106) and two-tier Warm + Cold Task Archive (TASK-86).

06Rules everything aims at

The 18 architecture non-negotiables (doc-7) and structural rules (doc-8) enforced across the workspace.

  • The browser is a client (ADR-0001)Clients never open SQL. Every state change goes through agentic-org-office.
  • One writer per store (ADR-0002, ADR-0021)One batching writer thread and one hash-chained acceptance journal per office; atomic file materialization and delete-and-rebuild parity.
  • Keys stay with the host (ADR-0016)The worker receives its office secrets key at verified launch. Neither worker nor web touches a host key store.
  • Replaceable storage engine (ADR-0018)org-store isolates engine mechanics behind traits; both SqliteEngine and in-memory MemoryEngine run the full conformance suites today, keeping PostgreSQL possible later.
  • Fast common commands (ADR-0014, Rule 18)Single-digit ms one-shot and 1 ms median / 2 ms p95 in session attach for routine reads/sends/tasks; no command holds a caller past 90 s.
  • Works alone, with narrow exceptionsOffices mint task numbers locally (T-B37, ADR-0019) and run office_local model bindings offline. Shared multi-office hq_pool permits (TASK-2) and HQ-centralized Codex refresh (ADR-0032 d6) are the recorded exceptions.
  • UUIDv7 everywhere (TASK-15)RFC 9562 UUIDv7 IDs are immutable across foreign keys, sync, wire APIs, and filenames.
  • Non-destructive mid-turn delivery (ADR-0035, Rule 11)Messages never abort a busy turn. Supported runtimes deliver coalesced addressed messages at safe step boundaries (StepHook / NativeSteer); only explicit authorized Stop/Interrupt or safety/stall stops abort a turn.
  • Credentials stay office-localNever in Git, command payloads, journals, or logs. Agents never hold Git push tokens or raw OAuth tokens in child tool env (CLAUDE_CODE_OAUTH_TOKEN_FILE_DESCRIPTOR + CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1, Codex shell_environment_policy).
  • macOS, Linux, and containers (ADR-0017)All OS variation lives strictly behind org-platform and org-platform-host (TASK-63 removed all remaining allowlist predicates). Unimplemented adapters fail closed.
  • Apps compose crates, zero cycles (doc-8)Binaries stay thin (agent-os is 9 lines; agentic-org-office is 32 lines); domain crates define consumer-owned ports; org-host never depends on org-office.
  • Fail closed, zero mocks in prodMissing capability shows unavailable; UI productionImportGuard errors on static mock imports (TASK-12).
