01Process topology

One named instance runs as one OS user on macOS, Linux, or inside a container. The OS service manager (or container foreground entrypoint) starts agentic-org serve; the host starts and supervises everything else.

Wire & protocol facts

  • Local frames are UTF-8 JSON lines (1 MiB cap on office socket; 4 MiB cap on agent runtime stdio framer). Requests carry id; events carry event.
  • agentic-org-web serves HTTP/1.1 + text/event-stream SSE (no WebSocket), and org-office-server terminates Org-CA mutual TLS directly for multi-office federation.
  • All 92 agent/human product CLI commands derive from one shared org-command CommandTable in org-agent-cli.

SQLite schema inventory & engine replaceability (ADR-0018)

  • Four executable SQL schema contracts (docs/design/organization-data/): schema.sql (79 tables, 12 views, 86 triggers, 65 indexes), messaging-schema.sql (13 tables, 9 indexes), budgets-schema.sql (10 tables, 16 triggers, 4 indexes), and private-notes-schema.sql (4 tables, 10 triggers, 5 indexes).
  • Dual-engine parity runs today: crates/org-office/src/store/open.rs is the single composition seam selecting EngineChoice::Sqlite vs EngineChoice::Memory. Every store family runs identical conformance and delete-and-rebuild tests on both engines, keeping PostgreSQL clean to drop in later.
  • Companion store exclusions (open.rs:636-658): OfficeStore rebuilds skip companion prefixes (accounting, budgets, authority/agent-execution, office-local auth, sessions, agents, tls, replication, and exact security/{git-https-helper,git-ssh-key,git-known-hosts}) while failing closed on any unknown or smuggled file.

How a change is stored Runs in v1 (ADR-0021)

  1. Writer (org-store)Single writer thread batches up to 64 operations, executes pure domain validation against the projection, and frames a hash-chained journal entry containing receipts and exact file bytes.
  2. Acceptance journalAppends to the office's single acceptance journal (commit point). Ack::Committed ops acknowledge once committed to SQLite; Ack::Durable ops wait for group flush.
  3. FlusherGroup-flushes journal to disk, confirms custody, materializes canonical files atomically under durable/, and runs WAL checkpointing. A failed flush halts the office rather than silently continuing.
  4. RebuildDeleting runtime/<office-id>/ (office.db and all 5 protected/*.db) rebuilds cleanly from durable/ using the exact same projectors as normal writes.

06Browser request path Runs in v1

agentic-org-web serves 13 domain route modules plus SSE over HTTP by default (opt-in HTTPS per ADR-0033) and supports authless local HQ mode by default (opt-in account sessions per ADR-0034).

  1. Browser → webIn authless local HQ mode, requests proceed directly into onboarding or domain views under the local owner identity. When account auth is opted in, POST /api/v1/session/sign-in verifies credentials via org-host, sets an HttpOnly instance cookie, and returns a 256-bit X-Org-Session-Proof.
  2. Browser → webEvery mutation carries a UUIDv7 operation_id, typed parameters, Origin/Host checks, and (when auth is enabled) cookie + proof header.
  3. Web → officeForwards typed commands over a host-granted ChannelKind::Web file descriptor with the caller's human principal and host grant.
  4. OfficeAuthorizes every call (Rule 9) and commits atomically via org-store.
  5. Web → browserReturns completed (200), accepted (202), rejected, or unknown (504, resolved via GET /api/v1/operations/{kind}/{id} using the same operation_id). Live updates stream over text/event-stream SSE.

09Providers, usage and budgets Runs in v1

All three control contracts are built and wired on v1 (TASK-53 L1–L3, TASK-54 L4, TASK-79 subscription usage, ADR-0032 enrollment).

  • Provider connections & pools (protected/providers.db): Ordered pools (1..64 connections), per-office wrapped bindings, live model discovery (valid ≤ 300 s), office_local offline admission vs hq_pool 60 s quota permits (renewed every 10 s), rate-limit cooldowns, and same-model failover. Remaining: live UI wiring for /settings/agents (TASK-114.2) and vault-native OAuth refresh replacing host claude -p ok refresh (TASK-132).
  • Immutable usage & cost accounting (durable/accounting/ + protected/accounting.db): Append-only JSONL events capturing input/output/cache-read/cache-write tokens, micro-USD estimates pinned to immutable price versions, snapshot attribution at consumption time, superseding corrections, and subscription daily/weekly usage tracking in Financials UI (TASK-79).
  • Budgets & holds (durable/budgets/ + protected/budgets.db): Task lifetime holds, independent agent daily/monthly holds, release warning-only caps, 80%/100% notices, and one-time 20% extension. Enforced between turns before admission (never aborts a running turn); unknown usage never blocks.

10Messaging Runs in v1

Office-first routing (ADR-0003) on isolated 0700/0600 protected/messaging.db (TASK-45–48, TASK-81, TASK-115, TASK-117).

  1. agent-os → local officeBinds via session token + peer-PID ancestry (checked against agent placement on satellites) and commits message locally with origin sequence.
  2. Same-office recipientWakes idle agent immediately or stages non-destructive mid-turn delivery (ADR-0035) if busy; pushes SSE notification to browser clients.
  3. Cross-office recipientDurable outbox streams to HQ over Org-CA mTLS; HQ deduplicates by origin office/incarnation/sequence, persists, and relays to destination satellite (triggering local wake + clean UUIDv7 source_id, TASK-157).
  4. Asks & channel watcherChatService tracks active AskWaiters so inline answers are not duplicated while busy askers without an active waiter receive answers mid-turn. Required asks suspend unanswered agents and resume the same session on answer (ADR-0020). Channel watchers run a lighter model with no tools to route channel answers into askers' inboxes (ADR-0024). Inbox snooze & resurfacing live (TASK-81).

Planned m-0 messaging upgrades: Channel Catch-Up Ladder watermarks/--since-read (TASK-99), end-to-end multimodal image attachments (TASK-98), and Chat UI Stop / Interrupt & Redirect / Steer controls (TASK-103). Known open bug: satellite chat.send(to="owner") handle resolution (TASK-141).

11Git and repositories Runs in v1

crates/org-git and org-office-server::git_calls run all network Git. Agents work inside isolated task worktrees and never hold push credentials (doc-35, TASK-51, TASK-161).

  1. HQRegisters repositories once and links them to projects with an explicit integration branch (agent-os repo register|attach).
  2. OfficeMaintains one bare cache per repository at runtime/<office-id>/repositories/<repository-id>.git.
  3. OfficePrepares isolated worktree on branch task/<ref>-<slug> under the employee's runtime path (agent-os worktree prepare).
  4. AgentEdits and commits locally (owner author + agent co-author).
