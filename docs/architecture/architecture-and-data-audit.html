Fault Line 1 Offline & Latency Contradictions

Doc 11 mandates HQ turn-permit acquisition and 10-second durable permit renewals for every turn, making ADR-0032's offline satellite execution impossible (turns abort within 40s) and placing 6–10 ms macOS F_FULLFSYNC writes on the exact same single writer/journal as 1 ms/2 ms hot-path messaging and task calls (Non-Negotiable #18). Worse, a non-deferred FK from local agent_execution_attempts to HQ-only connection_turn_permits breaks satellite office.db rebuilds (Non-Negotiable #1).

Fault Line 2 Spec-to-Code Chasm & Integration Cliff

The repository holds 35,480 lines of specs, 32 ADRs (12 added in 48 hours), 95 SQL tables, and 79k LOC of 93%-mocked UI, while zero browser requests reach an office (browser-to-office bridge B2 Q8 is still unowned) and v1 CI is red across 3 jobs. Parallel UI development against hand-authored mocks has already drifted behind the B2.1 backend model (memberships[] vs single home team).

Fault Line 3 Data Model & Privacy Structural Defects

Multiple verified defects in docs/design/organization-data/: task comments/checklists live inside a 64 KiB front-matter cap; release_progress disagrees with task_releases; Doc 17's required owner timezone change is blocked by its own SQL triggers; usage_*_totals views run O(groups × rows) correlated scans; 169 FKs lack indexes; and private DMs & owner-only budgets sit in plaintext office.db while private task notes got a separate database.

Fault Line 4 Boundary Leakage & Doc Drift

While org-store, org-office's SQLite boundary, and org-platform are genuinely exemplary, org-host violates ADR-0018 (rusqlite::ErrorCode exposed directly, no engine seam), apps/agentic-org-office (19.1k LOC, Ce=9) and apps/agent-os (3k LOC, org-spool) violate thin-binary rules, productionImportGuard stays in non-blocking report mode, and SCHEMA-COVERAGE.md, project-structure.md, and 5 ADRs contain stale or contradictory claims.

Structural Hotspots & Graph Telemetry

  • Extreme FK Hub (employees): Referenced by 80 foreign keys across the schema (organizations: 32, offices: 23, record_refs: 15, projects: 13), plus 7 triggers on employees.
  • 169 Unindexed Non-Trivial FKs: Including 7-column composite FK on agent_execution_attempts and critical query paths (private_task_notes(org, task_id), tasks(org, feature_id), usage_records(org, release_id), messages(org, thread_root_id)).

6. Storage Boundaries, Privacy Model & Schema-vs-Code Drift

Reconciling README.md, SCHEMA-COVERAGE.md, and actual Rust SQLite code

Drift SCHEMA-COVERAGE.md vs Actual Code

SCHEMA-COVERAGE.md:36 (dated 2026-11-18) claims 0/91 tables implemented and 16 tables with a "Different shape" in deleted org.db v3 / office.db v8.

Actual codebase truth (2026-11-20): crates/org-office/src/store/sqlite/schema.rs:11 executes docs/design/organization-data/schema.sql verbatim (all 91 tables + 12 views) plus 4 adapter tables (store_schema, store_cursor, store_sources, store_receipts). Ten organization-family tables are actively read/written today in store/sqlite/organization.rs: organizations, repositories, offices, office_codes, roles, teams, employees, reference_counters, reference_allocations, and record_refs. Old org.db/office.db schemas were deleted whole in B1b and are actively refused by office/folder.rs:20-54.

Boundary Plaintext Projection & Cross-Office Traps

Under ADR-0016, runtime/<office-id>/office.db is unencrypted SQLite. While private task notes were isolated into durable/private/task-notes.db, private human DMs (Doc 15), owner-only agent budgets/spend (Doc 17), and inline supervisor_command_receipts.response_json (Doc 11) remain inside shared plaintext office.db.

Meanwhile, durable/local/.../supervision/turns/<id>/input.json writes a second plaintext copy of visible messages outside durable/messaging/, and Entry 1 of durable/recovery/ embeds the wrapped Org CA key alongside public durable/state/ files.

8. Verified Architectural Strengths (Keep & Replicate)

High-discipline engineering patterns already proven in the repository

Rust Exemplar Engine & Platform Guards

org-store (#![deny(unsafe_code)], 1 dep on org-platform, memory engine + crash/rebuild testkit) and org-office's syn-based engine_boundary.rs (empty allowlist!) prove that clean ports-and-adapters boundaries work in this codebase. Likewise, org-platform (8 capabilities × macOS/Linux/refused, 0 workspace deps) plus platform_conditionals.rs and agentic-org-web/tests/dependency_closure.rs automate architectural governance instead of relying on prose.

Schema Zero Doc-to-SQL Drift & Relational Superkeys

All 91 tables use STRICT, embedded doc DDL matches schema.sql with zero diffs, and test_schema.py (111/111 passing in 1.15s) mutation-verified every trigger and unique index. Composite superkey FKs ((org, id, project_id), (org, id, home_team_id)) enforce cross-table ownership invariants declaratively in SQL.

Domain Sound Core Domain Decompositions

Office-coded task numbers (T-B37) deliver offline-safe unique references without coordination. Accountable team vs assigned team vs assignee vs immutable reporter is modeled cleanly. Accounting semantics (disjoint token buckets, integer micro-USD, immutable supersession, explicit null unknown) and single-writer chat file partitioning (participants/<id>/) are textbook designs.

Security Hardened BFF & Physical Note Isolation

agentic-org-web's privilege drop, OS confinement, publisher-signed static UI verification, zeroized frames, and digest-only auth tokens are production-grade. Separating private task notes into task-notes.db with a pending publish-receipt trigger preventing concurrent edits during cross-DB publish is a clean saga pattern.

9. Prioritized Remediation Roadmap

Sequenced to unblock dogfooding first without accumulating more rewrite debt

P0 — Fix Before Next Feature Slice

Resolve architectural contradictions & unblock milestone 1
  1. Own & build the browser-to-office bridge (B2 Q8) and freeze new speculative specs/ADRs until one real end-to-end in-org vertical slice (Teams/Tasks/Chat) runs without mocks.
  2. Decouple Doc 11 permits from offline & hot-path latency: Allow local/per-office-binding offline execution (reconciling ADR-0032), stop writing 10s permit renewals through the single durable journal/writer (use in-memory leases + coarse checkpointing or separate journal), and replace the cross-office immediate FK agent_execution_attempts → connection_turn_permits with a nullable/deferred audit ref so satellites can rebuild office.db.
  3. Move task comments & checklists out of the 64 KiB task YAML front matter into append-only sibling files (like Doc 15 messages) before implementing B4/B5.
  4. Fix 4 hard schema contradictions: align release_progress with task_releases; permit timezone boundary transitions in Doc 17 triggers; reconcile Doc 16:238 replication vs Docs 10 & 15; resolve Doc 04:109 vs 04:153 vs 01:139 instruction authority.
  5. Restore green v1 CI (7 macOS org-host tests, gitleaks baseline/history, bun audit).

P1 — Schema Integrity, Performance & Security

Before wiring B2–B7 & agent execution
  1. Add missing hot-path indexes & rewrite slow views: index private_task_notes(org, task_id), tasks(org, feature_id), task_document_versions(org, doc, ver), document_code_links(org, doc), usage_records(org, release_id, occurred_at), messages(org, thread_root_id), and active budget_holds; eliminate 3× scan in release_progress and O(N×M) correlated subquery in usage_*_totals.
  2. Close SQL integrity holes: change budgets.task_id FK to record_refs; add tombstones.office_code and kind CHECKs; fix affects_feature_id deferred/UPDATE bypasses; add FK + immutability triggers on document_versions / document_version_sources; give reused agent_process_instances standalone durable files; make Doc 11 FKs DEFERRABLE INITIALLY DEFERRED.
  3. Harden privacy & secret boundaries: isolate private DMs & owner-only budgets from plaintext office.db (or encrypt/separate like task-notes.db); move wrapped CA key out of Entry 1 journal; verify CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1 empirically before C2; tighten owner_only() to fail closed via org-platform.
  4. Flip UI productionImportGuard to 'error' and sever static imports of mock reducers/chat engines from production routes.

P2 — Structural Hygiene & Doc Sync

Reduce cognitive load & future engine/maintenance cost
  1. Bring org-host into ADR-0018 compliance: put hostdb behind an engine-neutral trait + memory testkit, remove rusqlite::ErrorCode from public error & writer.rs, and translate macOS keychain -25308 inside org-platform-host. Restrict org-office::Sqlite* re-exports to pub(crate).

Thin out binary crates & purge legacy: extract protocol/handlers from apps/agentic-org-office (19.1k LOC) and apps/agent-os (wire org-command, delete org-spool on B6); complete UUIDv7 wire cutover to delete from_wire_ulid; unify the 3 JSON hash codecs into 1 before v1 ships; consolidate Doc 11/16 duplicate receipt & process tables.

  4. Synchronize documentation: update SCHEMA-COVERAGE.md (10/91 active), project-structure.md (add org-platform-host & org-command), executable-migration.md, and reconcile ADRs 0002, 0006, 0007, 0011, 0027.
