# S0: Codex app-server

Status: **in progress**. This checkpoint verifies the local protocol and standalone
sandboxed commands. It does not complete S0 or verify a model-driven tool turn.
The brief is ada's `docs/design/agent-sessions.md` on `ada/agent-sessions`, with
the source research in `docs/research/agent-runtimes-control.md`.

## Run the offline probe

Tested on macOS 26.7.2 arm64, Codex CLI **0.167.0**, Node 26.13.0.
Pass the real absolute Codex binary path:

```sh
node spikes/codex/probe.mjs /absolute/path/to/codex
CODEX_S0_OUTPUT=/private/tmp/codex-s0.json node spikes/codex/probe.mjs /absolute/path/to/codex
# Skip the unchanged Git checks while iterating on sockets/profiles:
node spikes/codex/probe.mjs /absolute/path/to/codex --socket-only
```

The probe creates and removes a private directory under `/private/tmp`. Only its
child processes receive a temporary `HOME` and `CODEX_HOME`. They have no sign-in,
MCP configuration, installed plugins, API keys, or real organization data. The
session token is a synthetic fixture. It never sends `turn/start` and never calls
a model. The optional artifact contains sanitized JSON-RPC frames and stderr;
temporary root paths become `<TMP>`. It is written with mode 0600 on creation.

`/usr/bin/git` is an Xcode launcher on this Mac. Resolve Git with `xcrun --find git`
before sandboxing. The launcher stalled inside the sandbox; the resolved binary
committed successfully. The probe does this resolution automatically.

## Verified locally

| Check | Result / boundary |
| --- | --- |
| One `codex app-server --stdio` child, JSONL `initialize`/`initialized` | Works without authentication. |
| `command/exec`, `sandboxPolicy.type=workspaceWrite` | A workspace write succeeds; a write outside the explicit roots fails with `Operation not permitted`. |
| Session environment | The synthetic `ORG_SESSION_TOKEN` and `ORG_AGENT` survive the pinned shell environment settings in **standalone command/exec**. This does not prove model tool behavior or `msg.bind`. |
| Task worktree commit | Works with workspace, scratch, objects/refs/logs and literal own-admin paths. The admin folder's `gitdir` and `commondir` are excluded. |
| Shared Git files | Writes to `work.git/config`, `hooks/probe`, `HEAD`, `info/exclude` and the worktree's `commondir`/`gitdir` are refused. |
| Git config | `extensions.worktreeConfig=true`; bare setting moved to `config.worktree`. A task's `git config --worktree` succeeds. `GIT_CONFIG_COUNT` pins an empty hooks path, fsmonitor off, automatic GC/maintenance off, and commitGraph off. Global config is a generated fixture containing only commit identity. |
| Harmless Git diagnostic | `packed-refs.lock` is outside the task roots. Git printed a lock refusal, exited 0 and produced the expected commit. |
| Default Unix socket access | Legacy `workspaceWrite`, network off: fixture office connection fails with `EPERM`. |
| Explicit Unix socket allowlist | A named permissions profile plus `features.network_proxy=true` permits exactly the listed fixture socket. An unlisted socket and a separate direct TCP loopback listener both fail with `EPERM`. |
| Profile file carveout | A file inside the writable workspace marked `deny` cannot be read or overwritten. The original synthetic contents remain intact. |
| Profile thread startup | `thread/start` accepts `permissions`, `developerInstructions`, `approvalPolicy=on-request` and `approvalsReviewer=user` without a model call. |
| Empty thread resume | A fresh process rejects resume of a never-used thread with `no rollout found`. Resume after a real turn is still open. |

The environment pins exercised are:

```text
shell_environment_policy.inherit="all"
shell_environment_policy.ignore_default_excludes=true
shell_environment_policy.include_only=["PATH","HOME","TMPDIR","SHELL","LANG","ORG_AGENT","ORG_SESSION_TOKEN","GIT_CONFIG_NOSYSTEM","GIT_CONFIG_GLOBAL"]
```

This is the fixture list, not the final office list. The office must include its
other allowed environment names, including the indexed `GIT_CONFIG_*` names.
The default standalone `command/exec` also retained the fixture token here; don't
use that as evidence that model shell tools retain it without the pins.

## Exact sandbox fields

Schemas generated by the installed 0.167.0 binary establish:

- `thread/start`: `developerInstructions`, `config`, and either `sandbox` (an enum)
  or `permissions` (a named profile). There is no top-level `writableRoots`.
- `turn/start`: `sandboxPolicy.type="workspaceWrite"` with `writableRoots`, or
  `permissions` for a named profile. The schema says they cannot be combined.
- `thread/resume` accepts `developerInstructions` and `permissions` too.
- Legacy workspaceWrite has no deny-read or subtractive write-deny field. Its
  objects/info limitation requires the design's fallback when that policy is used.
  Named profiles can express a file deny, as verified above. The full Git and
  office deny lists under a profile are not yet verified.

The working socket profile overrides are equivalent to this TOML:

```toml
[features]
network_proxy = true

[permissions.office_probe]
extends = ":workspace"

[permissions.office_probe.network]
enabled = true
proxy_url = "http://127.0.0.1:0"
enable_socks5 = false

[permissions.office_probe.network.unix_sockets]
"/absolute/fixture/office.sock" = "allow"
```

`command/exec` selects it with `permissionProfile: "office_probe"`; threads select
it with `permissions: "office_probe"`. With no domain allow entries, the proxy
does not grant external destinations. Only local fixture destinations were probed.
This prototype extends `:workspace`, including its temporary-directory defaults;
the final office profile still needs explicit scratch roots and the full deny list.

Pass the **whole permissions table in one `-c` argument**. The installed CLI's
dotted override parser splits a period in a quoted socket filename into another
key. `features.network_proxy.enabled=true` is also rejected on this version;
`features.network_proxy=true` is the working form. No real config was changed.

## Still open before S0 is complete

- Real sign-in using the user's normal Codex home, with hooks, personal MCP and
  plugins/apps disabled; report remaining config/instruction/skill leakage.
- Cheap real `turn/start`, developer instruction behavior, `turn/steer`,
  `turn/interrupt`, approval request/answer and token usage events.
- Resume after a completed real turn with the complete policy replayed.
- Environment pins and the office socket from an actual model shell tool;
  `msg.bind` needs the real session-token/ancestry contract, not this echo fixture.
- Home-inside-a-repository commit, full profile Git denies and objects/info carveout.
- Tool process groups/detachment and cleanup after the runtime exits.
- Remote TUI is informational; no unauthenticated shared app-server is a candidate.
- Sanitized real-turn protocol fixtures for adapter contract tests.
