---
name: bounded-lookup
description: Delegate a precise read-only lookup or extraction when it saves discovery context; helpers never implement or approve work.
---

Use the active policy's lookup model/effort and codebase-scout role. Hybrid assigns
Haiku Low; codex-only assigns Sol 6.1 Low. Give one concrete question, bounded paths
and an output budget. Prefer a direct Repowise query or rg for an already known
symbol; avoid spawning a helper solely because its token rate seems cheaper.

Supply the selected scout role brief and relevant project guidance using
skill-routing. The helper reads those sources and returns its bounded preflight
acknowledgment; the lead records/validates it without granting shell or write tools.
Guidance about implementation does not expand the helper's lookup-only remit.

Only lookup/extraction/log summarization is allowed. No implementation, repairs,
acceptance, delegation or shell writes. Summarize existing test logs; do not launch
an unbounded test job. Return relevant paths/symbols, source evidence, concise
findings and explicit uncertainty. Stop when the question is answered. Route any
required change or nontrivial reasoning back to the lead with evidence.

Claude's helper has no shell/write tools. Native Codex roles inherit permissions:
from a writable parent, dispatch a separate `codex exec` with the lookup model,
`-c 'model_reasoning_effort="low"' -c 'agents.enabled=false' -s read-only`, bounded
prompt/output and recorded usage. Use the native scout only from an already
read-only parent. Never claim role prose alone enforces a sandbox. Source/index/memory results require
revalidation before decisions or implementation.
