---
name: security-boundaries
description: Implement or review Agentic Org credential, protocol, persistence and coordination changes against existing authority and recovery contracts.
---

Follow docs/design/documentation-authority.md, the owning organization-data document and docs/architecture-non-negotiables.md (rules 3, 7 to 10 and 12). Inspect the affected authorization, IPC and store tests.

- Processes and authority. The office is the only writer of organization data, and one office writes each file or stream. The host owns accounts, sessions and secrets. `agentic-org-web` holds no keys and opens no database. An agent reaches the product only through `agent-os` and its own office. The office authorizes every call: a person's request carries their principal and a host-issued grant; an agent's carries the binding of its run. Socket admission is never authorization, and no field on a record grants authority. Human, service and agent identities stay distinct.
- Secrets. No secret in Git, in an organization file or in the clear in a database. Data is not encrypted by the application (ADR-0016; increment A1 builds this): the host holds one office secrets key per office and passes it over the launch rendezvous; the office uses it only to wrap its private keys (the CA key now; TLS identity and invitation keys with a second office) as authenticated records in its own store. The host never receives those private keys; the web process and agents never receive the office secrets key. Until increment A1 lands, the office and host databases still use SQLCipher; do not add anything that depends on it.
- Sessions. Browser sessions are stored at the host as digests and survive restarts (ADR-0013); do not build on connection-bound browser sessions. Sessions on the host's local socket stay connection-bound, including the acknowledgement permission of ADR-0011.
- Agents. The isolation mode is part of the launch contract (ADR-0015); `dedicated-user` needs a privileged launcher and is never silently downgraded. An agent never holds the organization's secrets, a credential that can push, or another agent's sign-in.
- Acknowledgement. Only the committed-class operations ADR-0014 lists (messaging; task comments, checklist ticks and watching) may be acknowledged before the full flush. The class is declared in the domain crate and honoured by the store adapter, never by engine-specific code in a domain crate.
- Recovery delivery. For protected recovery delivery read ADR-0011 and ADR-0007 before implementation or review. The host's macOS bridge uses Objective-C ARC and blocks behind a fixed bounded C ABI: a fresh LAContext, no reuse, a single terminal result, lifetime-safe late callbacks, cancellation and deadline, and no global locks during OS UI. Verify the actual kernel peer, audit session, current console and foreground TTY; environment strings or PTY allocation never prove presence. Test production and test adapters separately; generated fixtures never establish signed native authentication. Keep the same-connection acknowledgement permission and durable acknowledgement and deletion reconciliation. The worker's public-record transport cannot carry the CA private key. Native bridge build inputs stay exact, confined and source-pinned.

A wire or runtime contract change updates every consumer together; nothing has shipped, so there is no migration, compatibility shim or retained protocol version. Keep signing and key-store namespaces as they are: they are persisted identities. Test unauthorized principals, replay and deduplication, rollback and partial failure, reconnect and cleanup where affected, with disposable roots. Private notes, keys and logs never go into shared organization Git. Nothing from the earlier coordination tool or its message queue is preserved or imported. Where contract authority is unclear or two security requirements conflict, decide inside the non-negotiables and record it, or agree it with the other lead when another increment depends on it.
