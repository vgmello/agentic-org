# Incrementally usable v1 delivery

Owner direction: finish the current full task-assignment contract, report its actual usable capability, then prioritize increments people can use end to end. Organization onboarding comes before team building and daily workflow; specialized cases follow unless they are a prerequisite. This records delivery order, not completed work or a replacement acceptance contract. Production security implementation, data preservation, recovery and local review remain gates for each affected increment. The owner deferred signing setup and authentic signed-release production verification until all other implementation is finished; see [the phase amendment](v1-release-signing-deferral.md).

| Order | Usable outcome | Completion evidence |
| --- | --- | --- |
| Current | Assign actual tasks through authenticated native/HTTP/UI paths, including independent team/employee clearing, durable history and original retry results. | Entire current assignment contract, real setup/adoption/static browser, required checks, fresh local reviews, exact-commit integration into v1-integration. |
| 1 | Install and start the service; create the first administrator and organization; enter its real workspace and resume after restart. | Functional setup/custody/authentication, persisted organization/HQ/repository identities and initial team/HR records, real browser sign-in, no seeded production accounts, retry/recovery proof. Keep generated development/test admission explicit; genuine signed-release install/setup verification belongs to the final phase. Reuse only the assignment prerequisite behavior that actually passes these gates. |
| 2 | Build and maintain teams and people within that organization. | Usable team/employee/role operations and views; stable IDs/numbers/handles, home-team and reporting/placement rules, authorization, persistence/reopen, meaningful validation errors and browser evidence. |
| 3 | Run the basic daily workflow: create and inspect tasks, assign work, change its state, and understand truthful history and queues. | Real task creation/read/update linked to delivered directory records and current assignment, public source/history integrity, conflict/retry/recovery and accessible end-to-end browser flows. |
| 4 | Let one supported coding-agent runtime perform useful work with necessary coordination and controls. | Real supported runtime adapter and instance/office binding, protected credentials, attribution, cancellation/fencing, minimum usage/budget enforcement before billable execution, and messaging continuity where required. No broad multi-runtime feature set is a prerequisite for proving one usable path. |
| 5 | Coordinate larger work through projects, milestones and releases when core users need them. | Real persisted planning relationships and usable views/commands; attach to the already delivered task workflow rather than a disconnected schema-only delivery. Bring a particular planning primitive forward if earlier milestones cannot operate without it. |
| Later | Broaden to advanced routing, additional runtimes/providers, deployment automation, release flags/changelogs and detailed accounting/reporting. | Separate vertical acceptance for each capability; any credential, budget, recovery or consistency control necessary for an earlier milestone moves forward with that milestone. |

The ordered unit is a usable outcome, not a document, crate, helper or percentage of code. Each delivery report must say what a user can do, which real path proves it, what remains unavailable, and the next usable increment. Do not label prerequisites as completed onboarding or count partial checkpoints as independently delivered features. Current coverage remains in v1-state.md; all selected v1 contracts remain in scope for the eventual product.

Final release phase, after remaining implementation: configure genuine signing/trust and complete signed-release setup/service/platform and signing-dependent production verification. Preserve all fail-closed checks throughout development; no unsigned-production mode is implied.
